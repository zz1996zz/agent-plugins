# PL 프롬프트 동작 사례

`cases.json`은 호출 경계·light 기록·reviewer 보고를 비교할 때 사용하는 입력과 판정 기준이다. 모델 실행 결과를 정답 코드에 하드코딩하지 않는다.

- 호출 평가는 카탈로그의 두 description으로 `select`(스킬 선택)와 본문 적용 후 `workflow`(기능 실행)를 따로 판정한다. 명시 alias 감사는 선택되더라도 기능 workflow는 실행하지 않는다.
- 양성 5개·음성 5개와 alias 감사 2개를 모두 확인한다. 음성은 PL workflow 자동 실행을 제외하는 경우이며 PL 자료 읽기나 요청한 감사 자체를 금지하는 뜻이 아니다.
- PL 본문 미제공 대조·기존 지침·수정 지침을 같은 입력으로 각각 독립 문맥에서 5회 이상 실행한다. 기본 CLI/harness 문맥이 남는 대조를 순수 무지침이라고 부르지 않는다. description으로 판단하는 호출 선택과 본문 적용을 구분하며, 전체 본문을 함께 제공한 모의 평가를 실제 카탈로그 선택·로드 증거로 해석하지 않는다.
- light·review 응답은 `checks`의 각 항목으로 직접 판정한다. 원문에서 실제 누락과 단순한 표현 차이를 구분한다. 저신뢰 우려를 남겼는지뿐 아니라 확인 방법·gate 처리도 확인한다.
- 서로 다른 사례의 원문이 섞이면 해당 사례만 별도 문맥에서 재평가한다. 두 gate PASS와 미해결 Minor의 부재, 자료 미제공과 실제 부재를 구분한다. 실제로 실행하지 않은 검사를 통과했다고 쓰는 문제와 정보가 부족한 항목을 과도하게 단정하는 문제도 따로 기록한다.
- Claude와 Codex를 구분해 모델·버전·원문·판정·실패·시간을 기록한다. 이 모의 평가는 호스트의 실제 skill 로드·권한·memo 저장·close를 입증하지 않는다. 실제 안전 E2E 및 필요한 smoke는 별도로 실행한다.
- 실행에는 인증과 토큰이 필요하다. 임시 디렉터리에서 도구를 비활성화하거나 읽기 전용으로 제한한다. 원문 로그에는 개인 경로가 들어갈 수 있으므로 커밋하지 않는다. 비용·개발 품질 개선은 별도 실측 없이 주장하지 않는다.
