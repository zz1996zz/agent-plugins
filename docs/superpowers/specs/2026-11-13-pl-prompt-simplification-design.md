# PL 프롬프트의 제한적 간소화

## 승인 범위

2026-11-13 사용자는 Codex·Claude의 독립 검토를 대조한 권고 뒤 `진행해`라고 승인했다. 호출 조건 정리(⑤), light의 해당 없는 절 표기(②), reviewer 보고 정리(④)만 구현한다. solo 경계 확대(①)와 최종 freshness 완화(③)는 제외한다.

## 목적과 제약

- 기능 실행과 PL 사용법 질문·읽기 전용 감사를 구분한다. 메타 요청에서 규모 판정·역할 실행·history 생성이 자동으로 시작되지 않아야 한다. 독립 리뷰를 명시적으로 요청한 사용자의 허가는 존중한다.
- light는 기존 헤딩을 유지한다. 실제 수행하지 않은 Synthesis·Challenges에 `n/a — light`를 허용한다. 역할 요약·Scope·핵심 결정·두 review gate·검증·Team·잔여 위험은 보존한다.
- reviewer는 근거와 영향이 있는 결함을 Findings에, 확인이 필요한 근거 부족 우려를 Unconfirmed concerns에 쓴다. 중요할 수 있는 우려에는 확인 방법을 적고 리드가 처리한다. tier나 낮은 confidence만으로 severity를 낮추지 않는다.
- helper·노트 템플릿·안전 hook·역할 수·모델 정책·검증/close 계약은 변경하지 않는다. 설치본·개인 설정도 변경하지 않는다.
- Python 3.9 이상, 생성기는 Python 3.11 이상, bash 3.2 호환을 유지한다. 사용자 요청 없는 커밋·푸시는 하지 않는다.

## 검토한 방식

1. 다섯 제안을 함께 적용: reviewer 생략과 fingerprint 계약 변경의 근거가 부족해 제외했다.
2. light 템플릿 헤딩 삭제: 기존 양식·테스트·복구 경로 변경이 필요하므로 제외했다.
3. 선택한 방식: 호출 조건과 조건부 작성·보고 규칙만 바꾼다. 기존 도구와 증거 구조를 그대로 사용할 수 있다.

## 변경 지점

- 두 SKILL.md: description을 실제 사용 조건으로 좁히고, 명시 호출에서도 메타 요청 분기를 적용한다.
- history.md: 해당 없는 분석·반론 절 표기를 허용한다. 실제 충돌이나 결정이 있는 경우는 기록한다.
- code-reviewer.md와 debate-protocol.md: Findings·Unconfirmed concerns의 처리 책임을 맞춘다. 중요한 미확인 위험이 열린 채 PASS가 되지 않도록 한다.
- 생성 TOML·양쪽 manifest·README 버전을 0.8.1로 동기화한다.
- 재사용 가능한 동작 평가 사례를 추가하고 baseline·수정안과 PL 본문 미제공 대조를 두 호스트에서 비교한다. 호출 선택 모의 평가와 실제 plugin 로드 검증을 구분한다.

## 검증

기여 안내의 로컬 매트릭스와 실제 안전 E2E를 임시 복사본에서 실행한다. 프롬프트 평가는 호출 양성·음성 각 5개 이상과 명시 alias 감사, light 기록, 중요한 저신뢰 우려를 포함한다. 관측 실패나 INVALID는 PASS로 세지 않는다. 시간·토큰·개발 품질 절감률은 이 평가로 입증했다고 주장하지 않는다.
